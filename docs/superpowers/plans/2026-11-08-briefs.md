# Briefs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename archetypes to briefs and add `/briefs` (overview) and `/briefs/:briefId` (one brief: criteria line + heat table of every pinned player), plus a status-menu toast when a player added to a brief's list is outside that brief's cohort.

**Architecture:** A brief is the existing archetype record, renamed in code and UI; storage keys stay. The scouting engine gains one ranking path (`buildCohortRanking` + `rankPlayer`) and one cohort rule (`cohortExclusions`) that scouting, the brief page and the toast all share. Two new views read the existing providers; no schema change.

**Tech Stack:** React 19, TypeScript (strict, `noUnusedLocals`/`noUnusedParameters`), Chakra UI 3, react-router-dom, IndexedDB via `idb`, Playwright (browser tests only).

**Spec:** `docs/superpowers/specs/2026-11-08-briefs-design.md` — read it before any task; this plan argues from it.

## Global Constraints

- Read `CLAUDE.md` first. Conventions: functional components, `I` prefix on interfaces where the codebase uses it, `@/*` alias available, no generic code comments (one short line only where genuinely non-obvious).
- **Fixed identifiers, never renamed:** the `archetypes` key in the `settings` store; the `scouting-filters` `localStorage` key; the `activeArchetypeId` property inside that stored JSON; `calculateArchetypes` in `src/utils/utils.ts`; everything under `src/processors/`; existing files under `docs/`.
- User-facing word is **brief** everywhere (UI copy, toasts, confirms, aria-labels).
- Testing policy: few tests, behaviour-only, Playwright only (no unit tests, no jsdom, no Vitest). Every kept test must be mutation-checked: break the behaviour it pins, see it fail, restore. Temporary probes are fine but are deleted before the task's commit.
- Never start the dev server. Playwright boots its own (`npm run test:browser -- <file>`).
- Commit messages: one short lowercase line, no attribution trailers, no mention of AI.
- Before every commit: `npx tsc -b` and `npm run lint` clean, plus the task's Verify command.

**Human verification (at finish, non-blocking):** the user runs `npm run dev` and checks, on a real import: `/briefs` lists briefs grouped by role; a brief page's heat cells read well in **both light and dark mode** (red → neutral → green, numbers legible); out-of-cohort tags look right; *Open in scouting* lands on the brief. Most likely wrong: heat colours too pale in dark mode or text contrast on strong green.

### Task 2: One cohort rule and one ranking path in the engine

**Files:**
- Modify: `src/utils/scouting-engine.ts`
- Create: `src/utils/scouting-columns.ts` — move here from `ScoutingView.tsx`: `STAT_ABBREVIATIONS`, `GROUP_ABBREVIATIONS` (exported as-is) and `getRoleClassForSide(config, side)` (exported, renamed `roleClassFor`)
- Modify: `src/views/ScoutingView.tsx` — import the moved pieces; build rows via the new engine API

**Interfaces — Produces:**
```ts
export type CohortExclusion = "minutes" | "league" | "role";
export function cohortExclusions(player: Player, RoleClass: RoleConfig["RoleClass"], rankedLeagues: Set<string>): CohortExclusion[];
// order of reasons: "role", "league", "minutes"; [] means in the cohort
export function rankedLeagueSet(rankings: LeagueRanking[]): Set<string>; // rank < 999, as today
export function asRole(player: Player, RoleClass: RoleConfig["RoleClass"]): Role; // wraps even a wrong-role player
export interface CohortRanking { roleConfig: RoleConfig; statGroups: StatGroup[]; sortedColumns: Record<string, number[]>; sortedGroupSums: Record<string, number[]>; }
export function buildCohortRanking(cohort: Role[], roleConfig: RoleConfig, statGroups: StatGroup[]): CohortRanking | null; // null when cohort is empty
export function rankPlayer(player: Role, ranking: CohortRanking): ScoutingRow;
export function roleClassFor(config: RoleConfig, side: Side): RoleConfig["RoleClass"]; // in scouting-columns.ts
```
`buildScoutingCohort(allPlayers, RoleClass, leagueRankings)` keeps its signature and keeps a player exactly when `cohortExclusions(...)` is `[]`. `computeScoutingData(cohort, roleConfig, statGroups)` keeps its signature and returns `cohort.map(p => rankPlayer(p, ranking))` (or `[]` when `buildCohortRanking` is null).

**Definition of done:**
- `asRole` uses a subclass of `RoleClass` whose static `isRole` returns `true` (the `Role` constructor checks `this.constructor.isRole`); cache one subclass per `RoleClass`.
- `rankPlayer` ranks stats with `getPercentileFromSorted` against `sortedColumns`, applies `roleConfig.derivedPercentileStats` formulas to the player's own percentiles, and ranks each group sum (inverted stats as `100 - p`) against `sortedGroupSums` — the same numbers `computeScoutingData` produced before for cohort members.
- `/scouting` numbers are unchanged: the full browser suite stays green. The numbers themselves (4 cohort strikers with `DrbPer90` 1,2,3,4 → 12.5, 37.5, 62.5, 87.5; an outsider at 3.5 → 75) are pinned by Task 4–5's tests; there is no TS runner for a scratch probe here.
- Out of scope: `getComparisonCohort` in `src/utils/role-percentiles.ts` (profile page) keeps its own filter; it is a different comparison and is not rerouted.

**Verify:** `npx tsc -b && npm run lint && npm run test:browser` → all pass.

**Definition of done — page:**
- Title *Brief: {name}*. Unknown id → *Brief not found* + link *Back to briefs* (`/briefs`).
- States, in order: briefs/notes/roster/rankings loading → spinner; briefs `loadError` → `LoadErrorNotice what="Briefs"`; notes `loadError` → `LoadErrorNotice what="Lists"`; roster error → `RosterErrorNotice`; rankings fetch error → `LoadErrorNotice what="League rankings"`. No league ranked → muted notice *No leagues are ranked yet. Briefs only rank players in ranked leagues — rank them on Leagues.* (*Leagues* links to `/leagues`, styled as scouting's), table still rendered below it.
- Header: name; criteria line = `briefCriteria(brief)` joined with ` · `: `roleLabel`; each threshold on a column the role has (`stat_*` in `roleConfig.statKeys`, `derived_*` in `derivedPercentileStats`, `group_*` in the role's groups, `age`, `wage`) as `{abbr} ≥ {min}`, `{abbr} ≤ {max}` or `{abbr} {min}–{max}` (abbr from `STAT_ABBREVIATIONS`/`GROUP_ABBREVIATIONS`, `Age`, `Wage`; wage values via `formatWage(Number(v))`); contract preset `season` → *contract by end of season*, `1y` → *contract within a year*, `2y` → *contract within two years*; `excludeInjuries` → *injury-free*; `excludedLeagues.length` n>0 → *n league(s) excluded*.
- *Open in scouting* button: `saveWorkingState({ filters: brief.filters, activeBriefId: brief.id })`, then `navigate("/scouting")`.
- No linked list → *This brief has no shortlist yet* + *Link list* (`useLinkBriefList`). Empty list → *No players on “{list}” yet — pin them from Scouting* (*Scouting* links to `/scouting`).

**Definition of done — rows (`buildBriefRows`):**
- One row per `list.uids` entry, in that order, `index` = 1-based position. Cohort = `buildScoutingCohort(roster, roleClassFor(config, side), rankings)`; ranking = `buildCohortRanking(cohort, config, groups)`.
- Present player: `exclusions = cohortExclusions(player, RoleClass, rankedLeagues)`; `row = ranking ? rankPlayer(asRole(player, RoleClass), ranking) : null`. Player with `Mins === 0` → no percentiles, tag *No stats* (replaces the *minutes* tag).
- Tags: `minutes` → *{Mins} min*; `league` → *Unranked league*; `role` → *Not a {roleConfig.name}* plus * ({side})* when side ≠ both, e.g. *Not a Fullback (left)*; article *an* before a vowel (*Not an Attacking Mid*). Put the article rule in one helper in `src/utils/briefs.ts` (`roleNoun(roleKey, side)` → `"a Fullback (left)"` / `"an Attacking Mid"`), used by Task 5 too.
- Absent player: dimmed, name = annotation `lastKnownName` ?? *UID {uid}*, club = `lastKnownClub` ?? `null`, every other practical field `null` (never `""` — `Table` sorts only `null` last), tag *Not in this snapshot*, a *Remove* button (`removeFromList(list.id, uid)`).
- Rows expose flat sortable keys; percentile keys hold the displayed value (inverted stats already `100 - p`); missing values are `null` so `Table` sorts them last.

**Definition of done — columns & cells (`BriefHeatTable`, uncontrolled `Table`, `defaultSortKey` = `index`, `defaultSortDirection` = `asc`):**
1. *#* (index, `firstSortDirection: "asc"`, so one click on *#* restores list order) · *Player* (status badge via `PlayerStatusControl`, name linking `/players/{uid}`, tags as small badges) 
2. *Age*, *Club*, *League*, *Wage* (`formatWage`), *Contract* (`displayDate` or `-`), *Mins*
3. Brief stats: each threshold key that is a `stat_*`/`derived_*`/`group_*` the role has, in scouting's column order (statKeys, then derived, then groups); `header` = abbreviation, `subheader` = the threshold (`≥ 60`, `≤ 40`, `40–80`); `headerTooltip` = full label.
4. Every role group not already in 3.
5. *All stats* checkbox above the table (off by default, plain state): adds every remaining `roleConfig.statKeys` entry and derived stat after the groups.
- Heat cell: background via the column's `cellProps` (fills the whole cell), number centred, `aria-label="{full label}: {rounded value}"` (full label from `STAT_LABELS` / group `label`). Colour: `d = (v - 50) / 50`; background `color-mix(in oklab, var(--chakra-colors-{green|red}-500) {round(|d| * 75)}%, transparent)` (green when `d > 0`, red when `d < 0`, transparent at 50); text `fg.default`. Empty cell when no value.
